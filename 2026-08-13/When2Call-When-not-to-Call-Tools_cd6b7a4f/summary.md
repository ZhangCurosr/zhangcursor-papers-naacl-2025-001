# 论文速读：When2Call-When-not-to-Call-Tools

## 一句话总结
论文提出了一个名为When2Call的新基准测试，用于评估大语言模型在何时应该（或不应该）调用外部工具的能力；同时开发了配套的训练数据集和一种基于多选题格式的偏好优化训练方法（RPO），显著提升了模型在工具决策和幻觉抑制方面的表现。

## 研究问题与动机
- 现有工具调用基准（如BFCL）主要关注"是否正确调用了工具以及参数是否正确"，但很少评估模型在何时**不应该**调用工具，例如当提供的工具无法回答问题或用户未提供足够参数时。
- 当前公开的预训练和微调数据集中，绝大多数样本都是"在系统提示中提供工具时进行工具调用"，而缺乏"不提供工具时模型应承认无法回答或追问缺失信息"的训练数据，导致模型倾向于过度调用工具甚至产生幻觉。
- 即使模型知道某个工具不相关（如在BFCL Irrelevance类别中），它们往往也只会简单地**不调用工具**，而不会进一步正确地选择"直接回答"、"追问更多信息"或"承认无法回答"等替代行为。
- 需要一种细粒度、可控的评估方式，能够同时量化模型的工具幻觉（tool hallucination）、答案幻觉（answer hallucination）和参数幻觉（parameter hallucination），以便开发者有针对性地改进模型。

## 核心贡献（创新点）
- **提出When2Call多分类基准测试**：通过多选题格式（直接回答/工具调用/追问/承认无法回答）同时评估模型何时应调用工具以及不应调用工具时的正确行为，相比BFCL Irrelevance提供了更细粒度的区分能力。
- **设计了面向工具决策的合成数据生成管道**：基于BFCL v2 Live和APIGen数据集，使用Mixtral 8x22B对问题进行分类和改写，自动生成了大量包含"无法回答"和"追问信息"正确答案的测试样本，并提供了配套的训练数据集。
- **验证了简单SFT训练的局限性并提出RPO训练方法**：发现直接将When2Call训练集加入SFT会导致模型过于保守、降低BFCL AST得分；而利用多选题格式构建偏好优化对（chosen/rejected）并结合奖励感知偏好优化（RPO）训练，能在提升When2Call表现的同时更好地维持BFCL工具调用准确率。
- **提出了工具幻觉、答案幻觉和参数幻觉的显式量化方法**：通过confusion matrix和提供评估脚本，允许开发者直接读取每类错误的比例，从而针对性地调整系统提示词或训练策略。

## 方法详解
- **基准构建**：将工具调用决策建模为四选一多选题，四个选项分别为：(a) 直接文本回答（由于所有问题都需要工具才能正确回答，此选项等价于幻觉）、(b) 工具调用、(c) 追问更多信息（追问缺失参数）、(d) 承认无法回答。
- **数据合成流程**：第一步用Mixtral 8x22B过滤BFCL Live或APIGen，筛选出需要实时信息或数据库访问才能回答的问题；第二步对每个保留的问题生成三种变体：保留原问题作为(b)正确工具调用样本，改写问题使正确答案为(c)追问信息，改写问题使正确答案为(d)无法回答，并为每个样本生成其余三个错误选项。
- **评估方式**：采用两种评估模式——①基于log-probability的多选题评估（适用于开源模型），报告Macro F1、长度归一化准确率和工具幻觉率；②LLM-as-judge评估（适用于GPT-4等闭源模型），由GPT-4-Turbo将模型生成的自由文本归类到四种选项之一。
- **RPO训练设计**：为每个正确回答选项（如"无法回答"）配对一个错误的拒绝回答（从剩余三类中均匀采样），构建成偏好对；同时额外构建正例对，确保工具调用能力不退化；使用KL惩罚值0.05，学习率4B模型9e-7、8B模型7e-7，10步warm-up。

## 实验与结果
- **数据集**：When2Call Test集包含3,652个问题（工具调用1,295题、追问1,062题、无法回答1,295题、直接回答0题）；训练集包含6,000题；偏好训练变体包含10,500题。
- **社区模型评估**：Llama 3.1/3.2、Qwen 2.5（0.5B~72B）、xLAM 7B/8x22B等模型在When2Call上的Macro F1仅17.9~37.8，且性能并不随模型规模单调提升；大部分模型在"无法回答"类别上得分极低，且工具幻觉率高（Llama 3.1 70B达57%）。
- **最强结果**：Mistral-NeMo-Minitron 8B经When2Call-RPO训练后，When2Call Macro F1达到52.4（较基线31.9提升64.3%），BFCL Irrelevance准确率提升至78.1%，BFCL AST准确率为62.5%（相比基线62.2%基本持平）。
- **闭源模型对比**：GPT-4o在LLM-as-judge评估下获得61.3 F1，GPT-4-Turbo-04-09获得64.6 F1，但仍存在22%~41%的工具幻觉率，表明仍有改进空间。
- **关键结论**：SFT训练容易导致模型过于保守（BFCL AST下降6.2%），而RPO训练在平衡"何时调用"与"何时不调用"方面更有效。

## 相关工作脉络
- **BFCL（Berkeley Function Calling Leaderboard）**：当前标准工具调用基准，含Irrelevance类别评估不提供正确工具的场景，但仅判断是否调用工具，不评估模型的替代行为；本文在细粒度和难度上与BFCL Irrelevance形成互补。
- **ToolSandbox**：评估工具调用能力的交互式基准，包含Insufficient Information类别，但同样只判断是否产生工具调用，不关注模型的后续行为。
- **ToolBeHonest**：侧重于评估工具幻觉的基准，通过任务可解性分类间接衡量模型是否会"想象出一个可以使用的工具"，但不提供直接的幻觉率计算和细粒度的四分类评估。
- **APIGen / Glaive v2 / Hermes**：公开的常用工具调用训练数据集，但均缺乏"无法回答"或"追问信息"类型的训练样本，这是导致模型工具幻觉率高的根本原因。
- **Meta-Tool Benchmark（Huang et al., 2024）**：评估模型决定是否使用工具以及使用哪个工具的基准，与本文关注点有部分重叠但评测维度不同。

## 局限性与未来方向
- 合成数据生成存在约8%的质量问题（如部分"无法回答"问题仍可被工具回答，或"追问"问题缺少真正缺失的参数），需要未来引入LLM-as-judge过滤步骤进一步清洗。
- 数据集假设所有问题的直接回答选项（a）均为幻觉，但现实中某些任务（如数学计算）使用工具可提高精度，未来基准需要能灵活处理此类"工具vs.直接回答"的权衡场景。
- 目前仅支持英文场景，多语言扩展和跨语言工具调用评估是未来的重要方向。
- 闭源模型评估仅覆盖GPT系列，未来需要扩展到Claude、Gemini等其他商业模型。

## 研究启发与可借鉴点
- **多选题格式评估的价值**：将开放式工具决策任务转化为四选一多选题，大幅简化了评估复杂度（无需解析工具调用或分类自由文本），同时支持高效的批量评测和幻觉率直接计算，这一思路可迁移到其他需要决策能力的评估场景。
- **RPO训练在负样本学习中的优势**：简单的SFT仅添加"不调用工具"的正例会导致模型过度保守，而RPO通过构建正负偏好对，在强化"何时不调用"的同时保留"何时应该调用"的能力，这种平衡策略可推广至其他"选择性输出"训练场景（如拒答、澄清等）。
- **混淆矩阵驱动的错误诊断**：本文通过提供四种幻觉类型的混淆矩阵和计算脚本，使开发者能精准识别模型的主要错误模式（如参数幻觉vs.答案幻觉），这种可解释的评估设计值得后续工作借鉴。
- **数据合成管道的复用**：使用大模型（Mixtral 8x22B）对现有高质量工具调用数据集进行自动改写和分类，以低成本生成包含"无法回答"和"追问"模式的训练数据，这一流程可直接复用于构建其他决策型基准的训练集。

## 关键术语表
- **When2Call**：本文提出的新基准测试，用于评估大语言模型何时应（或不应）调用外部工具，包含四种行为选项的多选题形式。
- **Tool Hallucination（工具幻觉）**：当系统未提供任何工具时，模型仍选择了"工具调用"选项，即凭空"想象"出了不存在的工具规格。
- **Answer Hallucination（答案幻觉）**：模型在未调用工具的情况下给出了直接文本回答，而这些问题的正确答案必须依赖工具才能获取。
- **RPO（Reward-aware Preference Optimization）**：一种偏好优化训练方法，利用多选题的正负答案对作为偏好数据来对齐模型行为，相比传统SFT能更好地平衡不同目标。
- **BFCL Irrelevance（无关工具类别）**：BFCL基准中评估模型在提供的工具与问题不相关时能否正确不调用工具的子类别，本文认为其难度较低且不够细粒度。
- **LLM-as-Judge**：使用另一个大语言模型（如GPT-4-Turbo）作为裁判，将目标模型的自由文本输出分类为四种行为类型之一的评估方式。
- **Macro F1**：本文采用的When2Call主要评估指标，对四种行为类别分别计算F1后取平均，避免某一类别样本过多主导整体得分。
- **Length-normalized Accuracy**：按答案文本字节长度归一化的准确率，用于减少答案表述长度对得分的人为影响。

## 可复现要素
- **数据集**：When2Call基准测试和训练数据集已公开发布（论文声明提供下载）。
- **代码/评估脚本**：论文提供了评估脚本和混淆矩阵计算工具，集成于LM Evaluation Harness框架中；详细实现见论文附录E。
- **训练超参**：4B模型学习率5e-6（SFT）/ 9e-7（RPO，warm-up 10步）；8B模型学习率4e-6（SFT）/ 7e-7（RPO，warm-up 10步）；RPO的KL惩罚值为0.05；训练使用8个NVIDIA H100 GPU节点，耗时约3-4小时/模型。
- **基线模型**：评测了Llama 3.1/3.2、Qwen 2.5、xLAM等社区开源模型以及GPT-4系列闭源模型。
